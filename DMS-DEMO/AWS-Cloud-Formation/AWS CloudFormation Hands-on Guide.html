Provision infrastructure with AWS CloudFormation

Describe an S3 bucket in a template, deploy it as a stack, change it safely with a change set, check it for drift, and delete it.

  • Level: beginner
  • Time: about 30 minutes
  • Cost: effectively free (one empty S3 bucket)

AWS CloudFormation lets you define AWS resources in a JSON or YAML template. CloudFormation creates, updates, and deletes those resources together as a single unit called a stack. You keep the template in version control and get the same result every time you deploy it.

Learning objectives

  • Read and write a CloudFormation template in YAML.
  • Validate a template and deploy it with the AWS CLI.
  • Preview and apply an update using a change set.
  • Detect configuration drift on a running stack.
  • Delete a stack and confirm its resources are gone.

Prerequisites

  • An AWS account and an IAM identity that can use CloudFormation and create S3 buckets.
  • AWS CLI v2 installed and configured (aws configure or an SSO profile).
  • A text editor and a terminal.
Set your Region once

Every command below uses your default Region. Check it with aws configure get region, or add --region us-east-1 (or your Region) to each command.

bash
aws sts get-caller-identity
aws cloudformation list-stacks --max-items 1
Checkpoint

The first command prints your account ID and ARN. The second returns without an access error.

Core concepts

TermWhat it means
TemplateA YAML or JSON file that declares the resources you want.
StackThe set of resources CloudFormation manages from one template.
ParametersValues you pass in at deploy time so one template can be reused.
OutputsValues the stack exposes after creation, such as a bucket name.
Change setA preview of what an update will add, modify, or replace.
DriftA difference between the template and the real resource, usually from a manual edit.

Architecture

Step 1. Write the template

Create a file named bucket.yaml. The bucket name combines your account ID, Region, and a suffix parameter, which keeps it globally unique.

bucket.yaml
AWSTemplateFormatVersion: "2010-09-09"
Description: CloudFormation lab - versioned S3 bucket

Parameters:
  NameSuffix:
    Type: String
    Default: cfn-lab
    AllowedPattern: "[a-z0-9-]+"
    Description: Lowercase suffix added to the bucket name

Resources:
  LabBucket:
    Type: AWS::S3::Bucket
    DeletionPolicy: Delete
    Properties:
      BucketName: !Sub "${AWS::AccountId}-${AWS::Region}-${NameSuffix}"
      VersioningConfiguration:
        Status: Enabled
      PublicAccessBlockConfiguration:
        BlockPublicAcls: true
        BlockPublicPolicy: true
        IgnorePublicAcls: true
        RestrictPublicBuckets: true

Outputs:
  BucketName:
    Description: Name of the bucket
    Value: !Ref LabBucket
  BucketArn:
    Description: ARN of the bucket
    Value: !GetAtt LabBucket.Arn
What to notice

!Ref returns the bucket name, !GetAtt reads an attribute, and !Sub fills in ${...} values. AWS::AccountId and AWS::Region are built-in pseudo parameters.

Step 2. Validate the template

bash
aws cloudformation validate-template --template-body file://bucket.yaml

Validation checks syntax and structure. It does not check that you have permission to create the resources or that the bucket name is free.

Checkpoint

The output lists your NameSuffix parameter and the description. A syntax error shows the offending line instead.

Step 3. Create the stack

bash
aws cloudformation create-stack \
  --stack-name cfn-lab-bucket \
  --template-body file://bucket.yaml

aws cloudformation wait stack-create-complete --stack-name cfn-lab-bucket

aws cloudformation describe-stacks --stack-name cfn-lab-bucket \
  --query "Stacks[0].[StackStatus,Outputs]"

To watch progress, open CloudFormation > Stacks > cfn-lab-bucket > Events in the console, or run aws cloudformation describe-stack-events --stack-name cfn-lab-bucket.

Expected result

The status is CREATE_COMPLETE and the outputs show your bucket name and ARN.

Step 4. Update with a change set

A change set shows the effect of an update before anything changes. Edit bucket.yaml and add a tag under Properties of LabBucket:

bucket.yaml (add under Properties)
      Tags:
        - Key: Project
          Value: cfn-lab
bash
aws cloudformation create-change-set \
  --stack-name cfn-lab-bucket \
  --change-set-name add-tag \
  --template-body file://bucket.yaml

aws cloudformation wait change-set-create-complete \
  --stack-name cfn-lab-bucket --change-set-name add-tag

aws cloudformation describe-change-set \
  --stack-name cfn-lab-bucket --change-set-name add-tag \
  --query "Changes[].ResourceChange.[Action,LogicalResourceId,Replacement]"

Read the Replacement column. False means the bucket is updated in place. True means CloudFormation would delete and recreate it, which you should avoid for resources that hold data. Apply the change when you are satisfied:

bash
aws cloudformation execute-change-set \
  --stack-name cfn-lab-bucket --change-set-name add-tag

aws cloudformation wait stack-update-complete --stack-name cfn-lab-bucket
Checkpoint

The stack status is UPDATE_COMPLETE. The bucket now has the Project tag.

Step 5. Detect drift

Change the bucket outside CloudFormation to see drift. Suspend versioning with the CLI, then run drift detection.

bash
BUCKET=$(aws cloudformation describe-stacks --stack-name cfn-lab-bucket \
  --query "Stacks[0].Outputs[?OutputKey=='BucketName'].OutputValue" --output text)

aws s3api put-bucket-versioning --bucket "$BUCKET" \
  --versioning-configuration Status=Suspended

ID=$(aws cloudformation detect-stack-drift --stack-name cfn-lab-bucket \
  --query StackDriftDetectionId --output text)

aws cloudformation describe-stack-drift-detection-status \
  --stack-drift-detection-id "$ID"

aws cloudformation describe-stack-resource-drifts \
  --stack-name cfn-lab-bucket --stack-resource-drift-status-filters MODIFIED
Expected result

Run the status command until it shows DETECTION_COMPLETE. The stack drift status is DRIFTED, and the resource drift output shows VersioningConfiguration differing from the template.

Fix drift in the template, not by hand

To restore the template's state, update the stack again, or set versioning back with aws s3api put-bucket-versioning --bucket "$BUCKET" --versioning-configuration Status=Enabled. Drift detection does not change anything on its own.

Sample template: all main sections

The lab template above is minimal. This larger sample uses every common template section: Parameters, Mappings, Conditions, Resources, and Outputs. It creates a log bucket and a DynamoDB table, and changes its behavior for dev or prod.

sample-app.yaml
AWSTemplateFormatVersion: "2010-09-09"
Description: Sample template - log bucket and orders table for dev or prod

Parameters:
  Environment:
    Type: String
    Default: dev
    AllowedValues: [dev, prod]
    Description: Deployment environment

Mappings:
  EnvSettings:
    dev:
      LogRetentionDays: 7
    prod:
      LogRetentionDays: 90

Conditions:
  IsProd: !Equals [!Ref Environment, prod]

Resources:
  LogBucket:
    Type: AWS::S3::Bucket
    Properties:
      BucketName: !Sub "${AWS::AccountId}-${AWS::Region}-${Environment}-logs"
      VersioningConfiguration: !If
        - IsProd
        - Status: Enabled
        - !Ref AWS::NoValue
      PublicAccessBlockConfiguration:
        BlockPublicAcls: true
        BlockPublicPolicy: true
        IgnorePublicAcls: true
        RestrictPublicBuckets: true
      LifecycleConfiguration:
        Rules:
          - Id: ExpireLogs
            Status: Enabled
            ExpirationInDays: !FindInMap [EnvSettings, !Ref Environment, LogRetentionDays]
      Tags:
        - Key: Environment
          Value: !Ref Environment

  OrdersTable:
    Type: AWS::DynamoDB::Table
    Properties:
      BillingMode: PAY_PER_REQUEST
      AttributeDefinitions:
        - AttributeName: OrderId
          AttributeType: S
      KeySchema:
        - AttributeName: OrderId
          KeyType: HASH
      PointInTimeRecoverySpecification:
        PointInTimeRecoveryEnabled: !If [IsProd, true, false]
      Tags:
        - Key: Environment
          Value: !Ref Environment

Outputs:
  LogBucketName:
    Description: Name of the log bucket
    Value: !Ref LogBucket
  OrdersTableName:
    Description: Name of the DynamoDB table
    Value: !Ref OrdersTable
    Export:
      Name: !Sub "${AWS::StackName}-OrdersTableName"
FeatureWhat it does in this template
AllowedValuesRejects any Environment other than dev or prod.
Mappings + !FindInMapLooks up log retention: 7 days for dev, 90 days for prod.
Conditions + !IfTurns on bucket versioning and table point-in-time recovery only in prod.
AWS::NoValueLeaves out the versioning property entirely when the condition is false.
No TableNameCloudFormation generates a unique name, so you can deploy the template more than once.
ExportLets other stacks in the same Region read the table name with !ImportValue.

Deploy the sample

bash
aws cloudformation validate-template --template-body file://sample-app.yaml

aws cloudformation create-stack \
  --stack-name cfn-sample-dev \
  --template-body file://sample-app.yaml \
  --parameters ParameterKey=Environment,ParameterValue=dev

aws cloudformation wait stack-create-complete --stack-name cfn-sample-dev

aws cloudformation describe-stacks --stack-name cfn-sample-dev \
  --query "Stacks[0].Outputs"
Checkpoint

The stack reaches CREATE_COMPLETE and the outputs list the bucket and table names. To see the prod behavior, create a second stack named cfn-sample-prod with ParameterValue=prod.

Clean up this stack too

Run aws cloudformation delete-stack --stack-name cfn-sample-dev (and the same for cfn-sample-prod if you created it). Empty the log bucket first if you added objects.

Validation

bash
aws cloudformation describe-stacks --stack-name cfn-lab-bucket \
  --query "Stacks[0].StackStatus"
aws s3api get-bucket-versioning --bucket "$BUCKET"
aws s3api get-bucket-tagging --bucket "$BUCKET"
  • Stack status is CREATE_COMPLETE or UPDATE_COMPLETE.
  • Versioning is Enabled (after you restore it).
  • The Project tag is present.

Troubleshooting

CREATE_FAILED: bucket already exists

Bucket names are global. Redeploy with a different suffix: --parameters ParameterKey=NameSuffix,ParameterValue=cfn-lab-2. A failed create leaves the stack in ROLLBACK_COMPLETE, so delete it before retrying.

AccessDenied or "not authorized"

Your IAM identity lacks a permission such as cloudformation:CreateStack or s3:CreateBucket. The stack Events tab names the denied action. Verify the exact permissions your organization requires.

Template format error

Re-run validate-template. Check YAML indentation (spaces only) and that short-form functions like !Sub are spelled correctly.

DELETE_FAILED: bucket not empty

CloudFormation cannot delete a bucket that holds objects. Empty it first, including old versions. See the cleanup step.

Cleanup

bash
aws cloudformation delete-stack --stack-name cfn-lab-bucket
aws cloudformation wait stack-delete-complete --stack-name cfn-lab-bucket
Checkpoint

aws cloudformation describe-stacks --stack-name cfn-lab-bucket now returns an error saying the stack does not exist. Also delete your local bucket.yaml if you no longer need it.
