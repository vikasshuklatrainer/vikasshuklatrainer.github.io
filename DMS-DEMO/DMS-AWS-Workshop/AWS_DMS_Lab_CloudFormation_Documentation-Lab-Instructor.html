1. Template Overview

This CloudFormation template provisions the infrastructure used by an AWS Database Migration Service (DMS) laboratory. It creates the source-side PostgreSQL environment, networking, supporting Lambda functions, sample-data initialization mechanism, and S3 package staging.

Important: The supplied template does not define an AWS::DMS::ReplicationInstance, DMS endpoints, or a DMS replication task. Those DMS objects are expected to be created separately for the migration exercise.

4. S3 Bootstrap and Lambda Package Copy

The template creates DMSLabCFNS3Bucket. A Lambda function named LambdaCopySource acts as a CloudFormation custom resource.

On Create or Update, the Lambda performs an S3 copy operation. On Delete, it deletes the copied object. The custom resource is therefore part of the CloudFormation lifecycle.

6. EC2 PostgreSQL Initialization Host

DMSLabInstance is an Amazon Linux 2023 t3.micro instance with a primary private IP of 10.0.0.40 and a public IP association.

User-data sequence

  1. Runs dnf update -y.
  2. Installs postgresql15 and git.
  3. Clones aws-database-migration-samples if not already present.
  4. Moves to the PostgreSQL sample database directory.
  5. Sets the PostgreSQL password environment variable.
  6. Gets the RDS endpoint address.
  7. Runs install-postgresql.sql using psql.
dnf update -y
dnf install postgresql15 git -y
git clone https://github.com/aws-samples/aws-database-migration-samples.git
export PGPASSWORD=admin123
psql --host=<RDS endpoint> --port=5432 \
     --dbname=sportstickets --username=adminuser \
     -f install-postgresql.sql

9. GenerateCDCData Lambda

The GenerateCDCData Lambda is deployed after CopySourceObject. Its code is stored in the stack-created S3 bucket and its environment contains the RDS endpoint:

HOST: !GetAtt RDSDMSLabDB.Endpoint.Address

The function is configured for VPC execution using the EC2 subnet and the lab security group.

11. S3 Cleanup Custom Resource

CloudFormation normally cannot delete a non-empty S3 bucket. The template addresses this with S3BucketHandler and the custom resource EmptyDMSLabCFNS3Bucket.

14. Using the Template with AWS DMS

Once the CloudFormation stack is successfully deployed, the resulting RDS endpoint can be used as the source side of the DMS lab.

Suggested DMS lab sequence

  1. Deploy the supplied CloudFormation template.
  2. Wait for the RDS PostgreSQL instance and EC2 initialization to complete.
  3. Retrieve the DMSInstanceEndpoint CloudFormation output.
  4. Create the DMS source endpoint using PostgreSQL and the RDS endpoint.
  5. Create the target endpoint for the selected target database.
  6. Create a DMS replication task for Full Load or Full Load + CDC.
  7. Run the task and validate the target data.
  8. Use the supplied CDC-generation mechanism to create source-side changes and observe DMS CDC behavior.
Scope boundary: Steps 4–8 describe how the template fits into the DMS exercise. The DMS resources themselves are not defined in this CloudFormation template.

15. Troubleshooting Guide

SymptomCheck
EC2 cannot connect to RDSVerify RDS security group ingress on TCP 5432 from DMSLabSG, subnet routing and RDS availability.
Sample database is not populatedInspect EC2 user-data/cloud-init logs and verify that the RDS endpoint is resolvable and reachable.
DMS cannot connect to PostgreSQLVerify the DMS replication instance networking, source endpoint host/port, credentials, RDS security group, and PostgreSQL replication configuration.
Lambda VPC execution failsCheck Lambda VPC subnet/security-group configuration and required network-interface permissions in its execution role.
Stack deletion fails on S3Check S3BucketHandler and the EmptyDMSLabCFNS3Bucket custom resource.
Source package copy failsVerify SourceBucket, SourceKey, and the permissions on LambdaCopySourceRole.
