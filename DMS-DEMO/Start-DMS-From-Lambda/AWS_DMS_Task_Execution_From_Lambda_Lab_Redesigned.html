Executing an AWS DMS Replication Task from AWS Lambda

Step-by-step lab guide for starting an existing AWS Database Migration Service (AWS DMS) replication task from a Python Lambda function using Boto3. Includes architecture, IAM permissions, configuration, code, testing, monitoring, troubleshooting, and a metadata-driven extension.

Scope: This lab assumes the DMS replication instance, source endpoint, target endpoint, and replication task already exist. Lambda controls the DMS task; it does not create those DMS resources.

1Architecture

Core idea: Lambda calls the DMS control-plane API. Lambda does not perform the data movement itself; the DMS replication task performs the migration.

2Prerequisites

  • DMS replication instance exists and is usable.
  • Source and target endpoints exist and their connection tests succeed.
  • A DMS replication task exists; a Full load task is recommended for this lab.
  • You can create/update IAM roles and Lambda functions.
  • You know the DMS task ARN.
  • For the simplest lab, create Lambda without VPC attachment. If Lambda is put in a private VPC subnet, it needs a network path to the AWS API it calls, such as NAT or an appropriate VPC endpoint.

3Get the DMS Task ARN

Step 3.1 Open AWS Console → Database Migration Service → Database migration tasks.
Step 3.2 Select the task that Lambda will start.
Step 3.3 Copy its ARN, for example:
text
arn:aws:dms:us-east-1:123456789012:task:ABCDEFG123456789

4Create the Lambda IAM Execution Role

Lambda assumes an execution role when the function runs. The trust policy must allow the Lambda service principal. Attach the AWS managed AWSLambdaBasicExecutionRole policy for CloudWatch logging and a custom DMS policy for the API calls.

4.1 Trust Policy

json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": {"Service": "lambda.amazonaws.com"},
    "Action": "sts:AssumeRole"
  }]
}

4.2 DMS Permissions

json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "DMSControl",
    "Effect": "Allow",
    "Action": [
      "dms:StartReplicationTask",
      "dms:DescribeReplicationTasks"
    ],
    "Resource": "*"
  }]
}
Production: use least privilege and scope resources where the action supports resource-level permissions. IAM Access Analyzer can help refine the policy based on actual access activity.

4.3 Console Steps

  1. IAM → Roles → Create role.
  2. Trusted entity: AWS service → Lambda.
  3. Attach AWSLambdaBasicExecutionRole.
  4. Create role, e.g. DMSStartTaskLambdaRole.
  5. Add the inline DMS policy above.

5Create and Configure Lambda

Step 5.1 Lambda → Functions → Create function → Author from scratch.
Step 5.2 Name: StartDMSReplicationTask.
Step 5.3 Runtime: choose a currently supported Python runtime; Python 3.14 is currently supported by Lambda.
Step 5.4 Select Use an existing role and choose DMSStartTaskLambdaRole.
Step 5.5 Create the function.

6Lambda Function Code

This version checks the DMS task status first, avoiding a duplicate start when the task is already running or starting.

python
import boto3
import os

dms = boto3.client("dms")


def lambda_handler(event, context):
    task_arn = os.environ["DMS_TASK_ARN"]

    print(f"DMS Task ARN: {task_arn}")
    print(f"Event: {event}")

    response = dms.describe_replication_tasks(
        Filters=[{
            "Name": "replication-task-arn",
            "Values": [task_arn]
        }]
    )

    tasks = response.get("ReplicationTasks", [])
    if not tasks:
        raise Exception(f"DMS replication task not found: {task_arn}")

    task = tasks[0]
    status = task["Status"]
    print(f"Current DMS task status: {status}")

    if status in ["running", "starting"]:
        return {
            "statusCode": 200,
            "message": "DMS task is already running or starting",
            "taskArn": task_arn,
            "status": status
        }

    if status in ["stopped", "failed"]:
        result = dms.start_replication_task(
            ReplicationTaskArn=task_arn,
            StartReplicationTaskType="start-replication"
        )

        new_status = result["ReplicationTask"]["Status"]
        print(f"DMS task start response status: {new_status}")

        return {
            "statusCode": 200,
            "message": "DMS task start requested",
            "taskArn": task_arn,
            "status": new_status
        }

    return {
        "statusCode": 200,
        "message": f"DMS task is in state '{status}'. No start attempted.",
        "taskArn": task_arn,
        "status": status
    }
Important: a successful Lambda response means that DMS accepted the start request. It does not mean the migration has completed. Monitor the DMS task separately.

7Start Type: Which Value Should We Use?

ValuePurposeRecommended lab use
start-replicationStart a task. It is the required first-start action for full-load, full-load-and-CDC, or CDC tasks.First run
resume-processingResume a previously executed task where applicable.Restart/resume scenarios
reload-targetReload target tables for applicable previously executed tasks.Explicit target reload scenario

9Execution Sequence

10Verify DMS

Open DMS → Database migration tasks and verify status, full-load progress, tables loaded, tables with errors, and table statistics.

bash
aws dms describe-replication-tasks \
  --filters "Name=replication-task-arn,Values=YOUR_TASK_ARN"

Equivalent CLI start:

bash
aws dms start-replication-task \
  --replication-task-arn YOUR_TASK_ARN \
  --start-replication-task-type start-replication

11CloudWatch Monitoring

Open Lambda → Monitor → View CloudWatch logs. Expected messages include:

text
DMS Task ARN: arn:aws:dms:...
Current DMS task status: stopped
DMS task start response status: starting

The AWSLambdaBasicExecutionRole policy provides basic Lambda logging permissions.

12Troubleshooting

SymptomLikely causeAction
AccessDeniedLambda role lacks DMS permissions.Check dms:StartReplicationTask and dms:DescribeReplicationTasks.
Task not foundWrong ARN, region, or account.Copy ARN from DMS and verify Lambda region.
Invalid resource stateTask already running/starting or otherwise not startable.Check status before starting.
Network timeoutLambda is in a private VPC without API connectivity.For this control-plane lab, remove VPC attachment or configure appropriate NAT/VPC endpoint connectivity.
Task starts but migration failsDMS endpoint, network, credentials, mappings, or source/target issue.Review DMS endpoint tests, task logs and table statistics.

13Optional: S3 Upload → Lambda → DMS

15Production Enhancements

  • Use least-privilege IAM.
  • Keep the task ARN in configuration/metadata rather than code.
  • Use Secrets Manager for secrets; do not put database passwords in Lambda code.
  • Add structured logs and correlation IDs.
  • Publish success/failure notifications using SNS or EventBridge.
  • Make the trigger idempotent so duplicate events do not start an already-running task.
  • Use Step Functions when the workflow requires wait/retry/branch/post-migration validation.
  • Create CloudWatch alarms for Lambda errors and DMS task failures.
