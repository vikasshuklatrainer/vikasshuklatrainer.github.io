1. Objective

This workshop demonstrates an incremental data-copy pipeline using AWS Glue. A Python simulator behaves like a source system and creates new CSV batches in Amazon S3. A Spark-based AWS Glue job reads the S3 source and uses Job Bookmarks so previously processed S3 input is not processed again.

Core lesson: incremental ingestion and incremental business-record upsert are different problems. A Job Bookmark tracks processed input; it does not automatically merge changed business keys into a target.

2. Architecture

INCREMENTAL DATA SIMULATOR | | batch CSV v +------------------------+ | S3 /source/orders/ | +-----------+------------+ | v +------------------------+ | AWS Glue Spark Job | | Job Bookmark | | CSV -> Parquet | +-----------+------------+ | v +------------------------+ | S3 /target/orders/ | +-----------+------------+ | v Athena

The generator is deliberately separate from Glue. It simulates source-system arrivals. The Glue Spark job performs the incremental copy.

4. IAM & Security

The CloudFormation template creates a Glue service role with the standard AWSGlueServiceRole managed policy and an inline policy scoped to the demonstration bucket. The bucket blocks public access and uses SSE-S3 encryption.

The role is assumed by glue.amazonaws.com. This follows AWS Glue's standard service-role model.

Production note: this is intentionally classroom-friendly. Production environments should further restrict permissions, use approved KMS keys where required, and separate operator/deployment permissions from runtime permissions.

5. Deploy

Recommended: helper script

cd aws-glue-incremental-demo
./deploy.sh

The helper creates the stack, discovers the bucket, uploads the Glue script, and uploads the first two sample batches.

Manual option

  1. Deploy cloudformation/glue-incremental-demo.yaml in CloudFormation.
  2. Accept CAPABILITY_NAMED_IAM.
  3. Copy the BucketName output.
  4. Upload scripts/glue_incremental_orders.py to s3://BUCKET/scripts/.
  5. Upload batch-001.csv and batch-002.csv to s3://BUCKET/source/orders/.
CloudFormation creates the Glue job definition before the script object exists. Upload the script before starting the job.

6. Initial Load

The package contains two initial batches: 10 + 5 = 15 orders.

s3://BUCKET/source/orders/
  batch-001.csv
  batch-002.csv
  1. Open AWS Glue → ETL jobs.
  2. Open glue-incremental-demo-job.
  3. Run the job.
  4. Open the run logs and observe the input count.

Expected first execution: approximately 15 input records and 15 records written to the Parquet target.

7. Job Bookmark

The job is configured with:

--job-bookmark-option=job-bookmark-enable

The source transformation uses a stable transformation_ctx="orders_source". The script also calls job.init() and job.commit().

Conceptually:

Run 1: batch-001 + batch-002 -> processed
Run 2: old batches skipped; new batch-003 -> processed
Run 3: old batches skipped; new batch-004 -> processed
The bookmark is about input processing state. It is not an upsert engine.

8. Simulated Incremental Data Generator

The generator creates a fresh CSV object with a unique batch name and uploads it to the source prefix.

Install

pip install boto3

Generate ten new records

python scripts/incremental_generator.py \
  --bucket YOUR_BUCKET \
  --batch 3 \
  --records 10

Generate seven shipped orders

python scripts/incremental_generator.py \
  --bucket YOUR_BUCKET \
  --batch 4 \
  --records 7 \
  --status SHIPPED

The generated object will look like s3://YOUR_BUCKET/source/orders/batch-003.csv.

Classroom trick: run the Glue job twice without generating another file. Then generate a new batch and run again. This makes the incremental behavior easy to see.

10. INSERT vs UPDATE

The file batch-003-update-demo.csv intentionally contains existing business keys:

1002  COMPLETED -> CANCELLED
1003  SHIPPED   -> DELIVERED
1016  NEW       -> INSERT
1017  NEW       -> INSERT

If this file is newly discovered by the bookmark, Glue can ingest all four records. However, this demonstration job uses append mode, so 1002 and 1003 do not replace older target records automatically.

Key teaching point: Bookmark = “have I processed this input?”; Upsert = “what should happen to this business key in the target?”

For a production-style upsert extension, use a table/storage technology and pattern that supports MERGE semantics, such as Apache Iceberg/Hudi or a database MERGE workflow.

11. Athena Validation

Create an external table over the Parquet target:

CREATE EXTERNAL TABLE IF NOT EXISTS orders_incremental (
  order_id string,
  customer_id string,
  product_id string,
  quantity int,
  amount decimal(18,2),
  status string,
  last_updated timestamp,
  ingestion_run string
)
STORED AS PARQUET
LOCATION 's3://YOUR_BUCKET/target/orders/';

Queries

SELECT count(*) AS total_rows
FROM orders_incremental;
SELECT status, count(*) AS orders
FROM orders_incremental
GROUP BY status
ORDER BY orders DESC;
SELECT * FROM orders_incremental
ORDER BY last_updated DESC LIMIT 20;

12. Reset Bookmark

For teaching, reset the Glue job bookmark and run the job again. Previously processed input can become eligible again.

Because this lab target is append-only, replaying input can create duplicate records. This is intentional: it demonstrates why production pipelines need idempotent target design, deduplication or MERGE logic.

13. Cleanup

aws s3 rm s3://YOUR_BUCKET --recursive

Then delete the CloudFormation stack. The stack removes the S3 bucket, IAM role, Glue job, Glue database and Athena workgroup after the bucket has been emptied.

14. Troubleshooting

AccessDenied

Check the CloudFormation-created Glue role and the bucket policy. Confirm the job script and data are in the expected bucket.

Second run reads old files

  • Confirm bookmark is enabled.
  • Use the same Glue job name between runs.
  • Keep transformation_ctx="orders_source" unchanged.
  • Ensure job.init() and job.commit() are present.

Duplicates after bookmark reset

Expected with append mode. Bookmark state does not make the target idempotent.

Why not Python Shell for the ETL?

The simulator is ordinary Python, but the ETL is a Glue Spark job because Glue Python Shell jobs do not support Job Bookmarks.
