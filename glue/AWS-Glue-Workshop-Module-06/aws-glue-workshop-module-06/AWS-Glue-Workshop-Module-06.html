AWS Glue Workshop — Module 06

Workflow orchestration with AWS Glue Workflows and Triggers — turn the independent ETL jobs from Module 3 into a coordinated data pipeline.

WorkflowTriggersConditionalScheduleEventCloudFormation

1. Module Objectives

Goal: create a Glue Workflow that coordinates existing ETL jobs and teaches on-demand, conditional, scheduled and event-driven orchestration.
  • Understand a Glue Workflow as a container for related jobs, crawlers and triggers.
  • Create an on-demand start trigger.
  • Create a conditional trigger that waits for job success.
  • Run a multi-job dependency chain.
  • Understand scheduled triggers and cron expressions.
  • Understand EventBridge-based event triggers.
  • Pass safe job arguments from a trigger.
  • Monitor workflow runs as a graph.
  • Deploy the base orchestration with CloudFormation.
  • Clean up resources no longer needed from earlier modules.

AWS describes workflows as a way to visualize and manage complex ETL activities involving multiple jobs, crawlers and triggers. citeturn0search1turn0search10

3. Architecture

Glue Workflow glue-module6-sales-workflow │ ┌────────▼────────┐ │ ON-DEMAND │ │ Start Trigger │ └────────┬────────┘ │ ▼ ┌────────────────────────┐ │ Module 3 S3 ETL Job │ │ glue-module3-s3-sales │ └───────────┬────────────┘ │ SUCCEEDED ▼ ┌────────────────────────┐ │ CONDITIONAL TRIGGER │ │ after-s3 │ └───────────┬────────────┘ │ ▼ ┌────────────────────────┐ │ Module 3 RDS ETL Job │ │ glue-module3-rds-to- │ │ s3-etl │ └────────────────────────┘ Optional later: Schedule → Start Trigger EventBridge Event → Event Trigger More successful jobs → additional conditional branches

Glue triggers can be on-demand, scheduled, conditional or event based. Conditional triggers can wait for job completion states such as SUCCEEDED. citeturn0search0turn0search3

4. Workflow and Trigger Concepts

ComponentPurpose
WorkflowContainer and execution/monitoring boundary for related Glue jobs, crawlers and triggers.
On-demand triggerManual entry point for a workflow.
Conditional triggerStarts downstream actions when predecessor conditions are met.
Scheduled triggerStarts jobs/crawlers according to a cron schedule.
Event triggerStarts actions from events, with optional batching.

AWS recommends workflows for complex multi-job ETL operations rather than building increasingly complicated standalone trigger chains. citeturn0search7

5. Create the Same Workflow Using the AWS Console

Console-first alternative: Everything created by the Module 6 CloudFormation template can also be created manually in the AWS Glue console. This is the recommended path for students who want to understand how workflows are assembled rather than simply deploying infrastructure.

AWS's current workflow procedure is to create the workflow, add a start trigger, attach the first job/crawler, and then continue adding event/conditional triggers to build the graph. There is no separate "Save workflow" button after the graph is completed; adding the final trigger/action completes the workflow definition. citeturn0search1

5.1 Prerequisites

Make sure Module 3 has already been deployed and the jobs glue-module3-s3-sales-etl and glue-module3-rds-to-s3-etl exist.
Open the AWS Management Console.
Switch to the AWS Region where the previous Glue resources were created.
Open AWS Glue.
In the left navigation, under ETL, choose Workflows.

5.2 Create the Workflow

On the Workflows page, choose Add workflow.
For Name, enter glue-module6-sales-workflow.
Optionally enter a description such as Module 6 Glue ETL orchestration lab.
Leave the default run properties empty for the first exercise.
Choose Add workflow.
Select glue-module6-sales-workflow from the workflow list.
Open the Graph tab.

AWS documents this as the first step of manually building a workflow. A workflow contains jobs, crawlers and triggers; the recommended maximum is 100 total jobs, crawlers and triggers in one workflow. citeturn0search1

5.3 Add the On-Demand Start Trigger

On the workflow Graph page, choose Add trigger.
Choose Add new.
For Trigger type, choose On demand.
For Name, enter glue-module6-start.
Choose Add.
A new trigger node appears with an Add node placeholder.
Select the Add node placeholder.
Choose Add jobs/crawlers to trigger if that option is shown.
Select glue-module3-s3-sales-etl.
Choose Add.
Expected graph: 
glue-module6-start
        │
        ▼
glue-module3-s3-sales-etl

An on-demand trigger fires when activated manually. AWS's console documentation describes the same Add trigger → On demand flow. citeturn0search0turn0search1

5.4 Add the Conditional Trigger

On the workflow graph, select the glue-module3-s3-sales-etl job node.
Use the node's Add trigger / Add trigger placeholder option.
Choose Add new.
For Trigger type, choose Event / Job events depending on the current console wording.
Give it the name glue-module6-after-s3.
Configure the watched job as glue-module3-s3-sales-etl.
Set the completion condition to Succeeded.
Add glue-module3-rds-to-s3-etl as the action/job to start.
Enable the trigger when prompted.

A conditional/job-event trigger can watch a previous job for states such as SUCCEEDED, FAILED or other completion states. AWS's current console calls this a conditional trigger / job events trigger depending on the UI path. citeturn0search0turn0search8

5.5 Verify the Graph

Confirm the first trigger is connected to the S3 ETL job.
Confirm the conditional trigger watches the S3 ETL job.
Confirm the conditional trigger starts the RDS ETL job.
Make sure there is no accidental direct connection from the start trigger to the RDS job.
Read the graph from left/top to right/bottom and explain the dependency to another student.

5.6 Run the Workflow from the Console

Return to the Workflows list.
Select glue-module6-sales-workflow.
Choose Run / Start workflow run.
Confirm the run.
Open the workflow's Runs or run-history view.
Open the latest run graph.
Watch the S3 ETL job move from pending/running to SUCCEEDED.
After success, verify that the conditional trigger fires and starts the RDS ETL job.
Open the RDS job run and inspect its logs.

AWS documents that an on-demand workflow can be started from the Glue console and that the workflow run graph can be used to identify failed nodes. citeturn0search11

5.7 Demonstrate Failure Handling

Before running this exercise, make a controlled temporary failure in the S3 ETL job.
Start the workflow.
Observe that the S3 ETL job fails.
Inspect the workflow graph.
Confirm that the conditional trigger does not start the RDS ETL job.
Repair the S3 job.
Run the workflow again.
Confirm the S3 job succeeds and the downstream RDS job now starts.
Teaching point: this is the key difference between simply running two jobs and orchestrating them. The workflow expresses a business/data dependency: do not execute the downstream stage until the upstream stage succeeds.

5.8 Create a Scheduled Start Trigger in the Console

For a second exercise, create a separate scheduled workflow or replace the on-demand start trigger with a schedule.

Open the workflow graph.
Choose Add trigger.
Choose Add new.
Select Schedule.
Give it a name such as glue-module6-schedule-test.
Choose a low-frequency schedule for the classroom, such as every hour.
If the console provides a custom schedule option, inspect the generated cron expression.
Attach the S3 ETL job as the action.
For classroom safety, leave the schedule disabled until students are ready to test it.

AWS Glue scheduled triggers use cron expressions; the console supports predefined frequencies and a Custom option. citeturn0search1turn0search3

Cost/safety: a scheduled trigger can continue launching Glue jobs after the class ends. Always disable the trigger when the exercise is complete. AWS provides Enable/Disable trigger controls in the Glue console. citeturn0search6

5.9 Create an EventBridge Start Trigger in the Console

This is an optional advanced exercise. It demonstrates an event-driven workflow instead of a clock-driven workflow.

Open the workflow Graph.
Choose Add trigger → Add new.
Select EventBridge event.
Give the trigger a name such as glue-module6-s3-event-start.
Configure the event source/pattern required by the exercise.
Optionally configure an event batch size and batch window.
Attach the first job to the trigger.
Create/enable the trigger.
Generate the corresponding event and observe the workflow start.

AWS Glue supports EventBridge events as workflow start triggers, including optional batching based on event count or a time window. A common pattern is starting a workflow when an S3 object arrives. citeturn0search7turn0search9

6. Module 6 CloudFormation Template

The template creates only the orchestration layer:

  • One AWS::Glue::Workflow
  • One on-demand AWS::Glue::Trigger
  • One conditional AWS::Glue::Trigger

AWS CloudFormation directly supports both Workflow and Trigger resources. citeturn0search0turn0search1

AWSTemplateFormatVersion: '2010-09-09'
Description: AWS Glue Workshop Module 06 - Workflow orchestration

Parameters:
  S3EtlJobName:
    Type: String
    Default: glue-module3-s3-sales-etl
  RdsEtlJobName:
    Type: String
    Default: glue-module3-rds-to-s3-etl
  WorkflowName:
    Type: String
    Default: glue-module6-sales-workflow
  StartTriggerName:
    Type: String
    Default: glue-module6-start
  AfterS3TriggerName:
    Type: String
    Default: glue-module6-after-s3

Resources:
  GlueWorkshopWorkflow:
    Type: AWS::Glue::Workflow
    Properties:
      Name: !Ref WorkflowName
      Description: Module 6 workflow
      MaxConcurrentRuns: 1

  StartTrigger:
    Type: AWS::Glue::Trigger
    Properties:
      Name: !Ref StartTriggerName
      Type: ON_DEMAND
      WorkflowName: !Ref GlueWorkshopWorkflow
      Actions:
        - JobName: !Ref S3EtlJobName

  AfterS3Trigger:
    Type: AWS::Glue::Trigger
    DependsOn:
      - StartTrigger
    Properties:
      Name: !Ref AfterS3TriggerName
      Type: CONDITIONAL
      StartOnCreation: true
      WorkflowName: !Ref GlueWorkshopWorkflow
      Predicate:
        Logical: AND
        Conditions:
          - LogicalOperator: EQUALS
            JobName: !Ref S3EtlJobName
            State: SUCCEEDED
      Actions:
        - JobName: !Ref RdsEtlJobName

7. Deploy the Module 6 CloudFormation Stack

Deploy Module 3 first so the referenced ETL jobs exist.
Open CloudFormation → Create stack → With new resources.
Upload aws-glue-module-06-workflow.yaml.
Use the default workflow and job names if Modules 3 was deployed with the workshop defaults.
Create the stack.
Open AWS Glue → Workflows and find glue-module6-sales-workflow.
The stack references existing jobs by name. CloudFormation does not import or manage those jobs; it only creates the workflow and triggers around them.

8. Run the Workflow

Open the workflow graph.
Confirm the on-demand start trigger is present.
Start the workflow from the console.
The start trigger launches the S3 ETL job.
When the S3 job reaches SUCCEEDED, the conditional trigger fires.
The RDS ETL job starts.
Open workflow run details and inspect each node's state.

Dependent jobs are only started when their predecessor was started by a trigger, and dependency chains must descend from a single scheduled or on-demand trigger. citeturn0search3

10. Scheduled Trigger Exercise

AWS Glue scheduled triggers use cron expressions. citeturn0search0turn0search4

For a classroom exercise, create a scheduled trigger that starts the S3 ETL job every 30 minutes:

Type: SCHEDULED
Schedule: cron(0/30 * * * ? *)
StartOnCreation: false
Cost control: keep StartOnCreation: false during training. Enable the schedule only while students are actively observing it.

11. Event-Driven Trigger Exercise

AWS Glue supports event-based triggers and event batching. This is useful when a workflow should respond to arriving data rather than a fixed clock schedule. citeturn0search0turn0search9

Create an event-based Glue trigger in the console.
Associate it with the workflow.
Configure the event source according to the current Glue console options.
Optionally configure an event batching condition.
Send/test the corresponding event.
Observe the workflow start.

Keep this exercise conceptual unless the class also covers EventBridge in depth; the core Module 6 stack intentionally avoids creating additional event infrastructure.

12. Monitor Workflow Runs

Open the graph view.
Inspect each trigger and job.

Glue workflows record execution progress and status across the workflow's components and expose a visual graph in the console. citeturn0search10

13. Passing Job Arguments

Triggers can pass arguments to the jobs they start. AWS warns that job arguments may be logged, so secrets must not be passed as plaintext arguments. Use Glue Connections or Secrets Manager for credentials. citeturn0search5turn0search11

Actions:
  - JobName: !Ref S3EtlJobName
    Arguments:
      --environment: workshop
      --output-format: parquet

Use this mechanism for non-secret runtime configuration such as environment, partition date or output mode.

Conditional trigger never firesPredecessor was started manually instead of by the workflow trigger.Start the workflow from its start trigger. Glue dependency chains require trigger-based execution.
RDS job starts unexpectedlyConditional trigger is active and predecessor succeeded.Deactivate the trigger or delete the workflow after the exercise.
Scheduled trigger keeps runningStartOnCreation/enabled schedule remains active.Disable the trigger immediately after the class exercise.
Job argument contains credentialsSecrets passed through trigger arguments.Remove the secret and use Glue Connection/Secrets Manager.
Workflow has too many concurrent runsMultiple starts or schedule overlap.Use MaxConcurrentRuns: 1 and avoid overlapping schedules.
