AWS Glue Workshop — Module 07

Advanced triggers and event orchestration — scheduled execution, EventBridge events, event batching, success/failure branches and runtime job arguments.

Advanced TriggersEventBridgeSchedulingBatchingBranching

1. Module Objectives

Goal: move from a simple sequential workflow to an event-driven orchestration pattern that can respond to time, events and job outcomes.
  • Understand scheduled versus event-driven workflow starts.
  • Use EventBridge events as a Glue workflow start mechanism.
  • Configure event batching.
  • Use conditional triggers for success and failure paths.
  • Pass non-secret runtime arguments to jobs.
  • Understand workflow default run properties.
  • Build the same design with CloudFormation and the AWS console.
  • Monitor and safely disable recurring triggers.

AWS Glue workflows can start from a schedule, on demand, or an EventBridge event; EventBridge starts can be single-event or batched. citeturn0search11turn0search7

4. Advanced Trigger Concepts

PatternWhen to use it
ScheduledPredictable periodic processing such as daily/weekly batch.
EventBridge eventStart processing when an external event occurs, such as an S3 object arrival.
Event batchingWait for N events or a maximum time window before starting the workflow.
Conditional successStart downstream processing only after upstream success.
Conditional failureRoute failures to notification/recovery/diagnostic work.

AWS Glue supports SCHEDULED, CONDITIONAL, ON_DEMAND and EVENT trigger types. Event batching supports a batch size of 1–100 events and a batch window of 1–900 seconds. citeturn0search0turn0search9turn0search10

5. Module 7 CloudFormation

The Module 7 template creates a separate workflow and four triggers:

  • Scheduled start trigger — disabled by default.
  • EventBridge start trigger — disabled by default.
  • Conditional success trigger.
  • Conditional failure branch.

The template uses EventBatchingCondition, which is supported by AWS::Glue::Trigger. citeturn0search0turn0search10

AWSTemplateFormatVersion: '2010-09-09'

Parameters:
  S3EtlJobName:
    Type: String
    Default: glue-module3-s3-sales-etl
  RdsEtlJobName:
    Type: String
    Default: glue-module3-rds-to-s3-etl
  WorkflowName:
    Type: String
    Default: glue-module7-event-orchestration

Resources:

  AdvancedWorkflow:
    Type: AWS::Glue::Workflow
    Properties:
      Name: !Ref WorkflowName
      MaxConcurrentRuns: 1

  ScheduledStart:
    Type: AWS::Glue::Trigger
    Properties:
      Type: SCHEDULED
      Schedule: cron(0 9 * * ? *)
      StartOnCreation: false
      WorkflowName: !Ref AdvancedWorkflow
      Actions:
        - JobName: !Ref S3EtlJobName
          Arguments:
            '--orchestration-mode': scheduled

  EventBridgeStart:
    Type: AWS::Glue::Trigger
    Properties:
      Type: EVENT
      StartOnCreation: false
      WorkflowName: !Ref AdvancedWorkflow
      EventBatchingCondition:
        BatchSize: 2
        BatchWindow: 300
      Actions:
        - JobName: !Ref S3EtlJobName
          Arguments:
            '--orchestration-mode': event

  AfterS3Success:
    Type: AWS::Glue::Trigger
    Properties:
      Type: CONDITIONAL
      StartOnCreation: true
      WorkflowName: !Ref AdvancedWorkflow
      Predicate:
        Logical: AND
        Conditions:
          - LogicalOperator: EQUALS
            JobName: !Ref S3EtlJobName
            State: SUCCEEDED
      Actions:
        - JobName: !Ref RdsEtlJobName
          Arguments:
            '--orchestration-mode': downstream-success

  S3FailureBranch:
    Type: AWS::Glue::Trigger
    Properties:
      Type: CONDITIONAL
      StartOnCreation: true
      WorkflowName: !Ref AdvancedWorkflow
      Predicate:
        Logical: AND
        Conditions:
          - LogicalOperator: EQUALS
            JobName: !Ref S3EtlJobName
            State: FAILED
      Actions:
        - JobName: !Ref S3EtlJobName
          Arguments:
            '--orchestration-mode': failure-demo
EventBridge permission: EventBridge must be permitted to notify the Glue workflow. AWS documents the glue:notifyEvent permission for the EventBridge-to-Glue integration. The console-created EventBridge workflow trigger handles the integration path for the classroom exercise; when automating the surrounding EventBridge configuration separately, verify this permission. citeturn0search8

7. Console Lab — Build Module 7 Manually

7.1 Create the Advanced Workflow

Open AWS Glue.
Choose ETL → Workflows.
Choose Add workflow.
Enter glue-module7-event-orchestration.
Optionally add description: Advanced trigger and event orchestration.
Choose Add workflow.
Open the workflow and select the Graph tab.

7.2 Create a Scheduled Start Trigger

Choose Add trigger.
Choose Add new.
Select Schedule.
Name it glue-module7-scheduled-start.
For the classroom, choose a low-frequency schedule.
For a custom schedule, use a cron expression such as cron(0 9 * * ? *).
Attach glue-module3-s3-sales-etl as the action.
Do not enable it yet.

AWS's console supports Schedule, On demand and EventBridge event start triggers, with Custom cron available for schedules. citeturn0search7

7.3 Create an EventBridge Start Trigger

Choose Add trigger → Add new.
Select EventBridge event.
Name it glue-module7-event-start.
Set the event batch size to 2 for the exercise.
Set the optional batch window to 300 seconds.
Attach glue-module3-s3-sales-etl.
Create the trigger but keep it disabled until the event exercise begins.

AWS documents that EventBridge start triggers can wait for a specified number of events or until the batch window expires. citeturn0search7turn0search11

7.4 Add the Success Dependency

Select the S3 ETL job node.
Add a new trigger.
Choose the job-event/conditional trigger option.
Name it glue-module7-after-s3-success.
Watch glue-module3-s3-sales-etl.
Choose Succeeded.
Add glue-module3-rds-to-s3-etl as the action.
Enable the trigger.

7.5 Add the Failure Branch

Add another conditional/job-event trigger.
Name it glue-module7-s3-failure-branch.
Watch the S3 ETL job.
Choose Failed.
For a classroom demonstration, point the branch to a harmless diagnostic/recovery job if available.
Do not point a failure branch back to the same production job unless you deliberately want to demonstrate retry-loop risks.
Recommended production pattern: a failure branch should normally call a notification, quarantine, diagnostic or recovery process—not blindly rerun the failed job.

7.6 Test Scheduled Execution

Enable the scheduled trigger.
Wait for the scheduled time or temporarily use a short classroom schedule.
Observe the S3 job start.
After testing, immediately disable the scheduled trigger.

7.7 Test EventBridge Execution

Enable the EventBridge trigger.
Generate the event configured for your exercise.
Send two events to demonstrate the BatchSize = 2 condition.
Observe that the workflow starts after the batch condition is met.
Alternatively, send one event and wait for the configured batch window to expire.
Disable the EventBridge trigger after testing.

AWS's EventBridge workflow integration uses the Glue notifyEvent permission so EventBridge can deliver the event to the workflow. citeturn0search8

8. Scheduled Trigger Deep Dive

Glue schedules use AWS cron syntax and are evaluated in UTC. For example:

cron(0 9 * * ? *)

means 09:00 UTC daily. AWS documents scheduled triggers as time-based triggers using cron expressions. citeturn0search2turn0search9

RequirementExample
Daily 09:00 UTCcron(0 9 * * ? *)
Every hourcron(0 * * * ? *)
Every 30 minutescron(0/30 * * * ? *)
Weekdays 08:00 UTCcron(0 8 ? * MON-FRI *)
Always check the schedule in UTC and disable recurring triggers after the classroom exercise. A trigger that remains enabled can continue launching Glue jobs.

9. EventBridge Trigger Deep Dive

EventBridge event triggers are useful for data pipelines where processing should begin because something happened rather than because a clock reached a time. AWS identifies S3 object arrival as a common use case. citeturn0search11

S3 PutObject │ ▼ EventBridge Event │ ▼ Glue Event Trigger │ ▼ Workflow │ ▼ S3 ETL Job

The event trigger can operate on one event or batch multiple events before starting the workflow.

10. Event Batching Exercise

Glue supports two batching controls:

PropertyMeaningRange
BatchSizeNumber of EventBridge events required.1–100
BatchWindowMaximum wait after the first event.1–900 seconds

For example, BatchSize=10 and BatchWindow=300 means the workflow starts when ten events arrive or five minutes pass after the first event, whichever happens first. citeturn0search10

11. Success and Failure Branching

S3 ETL │ ┌─────────┴─────────┐ │ │ SUCCEEDED FAILED │ │ ▼ ▼ RDS ETL Notification / Recovery / Diagnostics

Conditional triggers can watch job or crawler completion states and can use AND or ANY logic when multiple conditions are configured. citeturn0search2turn0search14

Advanced exercise: two upstream jobs

Create a trigger that starts a downstream job only when both upstream jobs succeed:

Predicate:
  Logical: AND
  Conditions:
    - Job A = SUCCEEDED
    - Job B = SUCCEEDED

Then create a second trigger using ANY to demonstrate an alert/recovery path when either upstream job fails.

12. Workflow Run Properties and Job Arguments

Workflow default run properties can be made available as arguments to jobs in the workflow. AWS documents workflow run properties as a way to pass configuration across jobs. citeturn0search7turn0search12

Good examples include:

  • environment
  • processing date
  • output format
  • source system
  • execution mode
Never pass passwords, API keys or other secrets as trigger/job arguments. AWS warns that job arguments can be logged. Use Glue Connections or Secrets Manager instead. citeturn0search6
